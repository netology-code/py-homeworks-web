# Практическое задание «Event loop. Asyncio»

## Информация для студентов

Уважаемые студенты! В этом задании вы примените на практике асинхронное программирование в Python. Вам предстоит загрузить данные о персонажах вселенной Star Wars из открытого API и сохранить их в базу данных PostgreSQL — полностью в асинхронном режиме, без блокирующих вызовов.

Почему это важно? В реальных проектах часто требуется массово загружать данные из внешних источников. Синхронный подход при этом крайне неэффективен — каждый HTTP-запрос блокирует выполнение программы. Асинхронный пайплайн позволяет выполнять десятки запросов параллельно, многократно ускоряя процесс.

## Выполнив это задание, вы:

- научитесь работать с `asyncio` и event loop в Python;
- освоите асинхронные HTTP-запросы с помощью `aiohttp`;
- научитесь асинхронно взаимодействовать с PostgreSQL через `asyncpg` (или `aiopg`);
- получите опыт создания миграций с помощью SQLAlchemy;
- научитесь разворачивать PostgreSQL в Docker-контейнере.

## Описание задания

### Источник данных

Вы будете работать с API **Star Wars API (SWAPI)**: `https://swapi.tech/api/people/`

Список всех персонажей доступен постранично:
```
GET https://swapi.tech/api/people?page=1&limit=10
```

Ответ содержит поля `total_records`, `total_pages`, `next`, `previous` и массив `results` со ссылками на каждого персонажа. Детальная информация о персонаже доступна по его URL:
```
GET https://swapi.tech/api/people/{id}
```

Данные персонажа находятся в `result.properties`.

### Описание полей персонажа

| Поле | Тип в API | Описание | Тип в БД | Примечание |
|------|-----------|----------|----------|------------|
| `id` | `string` (uid) | Уникальный идентификатор персонажа | `String` | Берётся из `result.uid` |
| `birth_year` | `string` | Год рождения (например, `19BBY`) | `String` | — |
| `eye_color` | `string` | Цвет глаз | `String` | — |
| `films` | `array[url]` | Список URL фильмов, в которых появлялся персонаж | `String` | Перейти по каждому URL, извлечь поле `title`, записать через запятую |
| `gender` | `string` | Пол персонажа | `String` | — |
| `hair_color` | `string` | Цвет волос | `String` | — |
| `height` | `string` | Рост в сантиметрах | `String` | — |
| `homeworld` | `url` | URL родной планеты | `String` | Перейти по URL, извлечь поле `name` |
| `mass` | `string` | Масса в килограммах | `String` | — |
| `name` | `string` | Имя персонажа | `String` | — |
| `skin_color` | `string` | Цвет кожи | `String` | — |
| `starships` | `array[url]` | Список URL звёздных кораблей | `String` | Перейти по каждому URL, извлечь поле `name`, записать через запятую |
| `vehicles` | `array[url]` | Список URL транспортных средств | `String` | Перейти по каждому URL, извлечь поле `name`, записать через запятую |

### Пример

Для персонажа Luke Skywalker (`https://swapi.tech/api/people/1`):

- `homeworld`: API возвращает `https://www.swapi.tech/api/planets/1` → переходим по ссылке → получаем `name: "Tatooine"` → в БД записываем `"Tatooine"`
- `films`: API возвращает массив из 4 URL → переходим по каждому → получаем `title` каждого фильма → в БД записываем `"A New Hope, The Empire Strikes Back, Return of the Jedi, Revenge of the Sith"`
- `starships`: аналогично → `"X-wing, Imperial shuttle"`
- `vehicles`: аналогично → `"Snowspeeder, Imperial Speeder Bike"`

### Что нужно сделать

1. **Развернуть PostgreSQL в Docker.** Подготовьте `docker-compose.yml` с сервисом PostgreSQL.

2. **Написать миграционный скрипт** (`models.py` или `migrate.py`). С помощью SQLAlchemy опишите модель таблицы `people` со всеми полями из таблицы выше. Все поля — строковые (`String`). Скрипт должен создавать таблицу в базе данных.

3. **Написать скрипт загрузки данных** (`load_data.py`). Скрипт должен:
   - Асинхронно получить список всех персонажей из SWAPI (82 записи);
   - Для каждого персонажа асинхронно загрузить детальную информацию;
   - Для полей-ссылок (`homeworld`, `films`, `starships`, `vehicles`) — асинхронно перейти по каждому URL и извлечь имя/название;
   - Асинхронно сохранить все записи в PostgreSQL;
   - Использовать **только асинхронные** библиотеки (`aiohttp` для HTTP, `asyncpg`/`aiopg` для БД).

4. **Убедиться**, что в базе данных сохранены все 82 персонажа с заполненными полями.

## Инструкция к выполнению

### Шаг 1. Подготовка окружения

Создайте файл `docker-compose.yml`:

```yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: swapi_user
      POSTGRES_PASSWORD: swapi_pass
      POSTGRES_DB: swapi
    ports:
      - "5432:5432"
```

Запустите контейнер:
```bash
docker compose up -d
```

Установите зависимости:
```bash
pip install aiohttp asyncpg sqlalchemy
```

### Шаг 2. Миграция — создание таблицы

Создайте файл `models.py`. Опишите модель `SwapiPeople` с помощью SQLAlchemy (declarative base). Все поля — `String`. Первичный ключ — `id`.

Создайте файл `migrate.py`, который подключается к базе и создаёт таблицу.

### Шаг 3. Скрипт загрузки данных

Создайте файл `load_data.py`. Реализуйте:

1. Получение списка всех персонажей через пагинацию API (`?page=N&limit=10`).
2. Параллельную загрузку детальной информации по каждому персонажу.
3. Для каждого персонажа — параллельное разрешение ссылок:
   - `homeworld` → GET запрос → извлечь `name`
   - `films` → GET запросы → извлечь `title` из каждого → объединить через `", "`
   - `starships` → GET запросы → извлечь `name` из каждого → объединить через `", "`
   - `vehicles` → GET запросы → извлечь `name` из каждого → объединить через `", "`
4. Асинхронную вставку записей в PostgreSQL.

Все HTTP-запросы и операции с БД должны быть асинхронными. Используйте `asyncio.gather()` или `asyncio.TaskGroup` для параллельного выполнения запросов.

### Шаг 4. Проверка результата

Подключитесь к базе и убедитесь, что данные загружены:
```bash
docker exec -it <container_id> psql -U swapi_user -d swapi -c "SELECT count(*) FROM people;"
```

Ожидаемый результат: `82`.

```bash
docker exec -it <container_id> psql -U swapi_user -d swapi -c "SELECT name, homeworld, films FROM people LIMIT 3;"
```

## Критерии оценки задания

### «Зачёт»

- PostgreSQL развёрнут в Docker (есть `docker-compose.yml`).
- Есть миграционный скрипт, создающий таблицу `people` со всеми 13 полями (все строковые).
- Скрипт загрузки данных использует только асинхронные библиотеки (`aiohttp`, `asyncpg`/`aiopg`).
- Поля-ссылки разрешены: в БД хранятся имена/названия, а не URL.
- В базе данных сохранены все 82 персонажа с корректно заполненными полями.
- Код запускается без ошибок.

### «На доработку»

- Используются синхронные библиотеки (`requests`, `psycopg2`) вместо асинхронных.
- Поля-ссылки не разрешены (в БД хранятся URL вместо имён).
- В базе данных менее 82 записей.
- Отсутствует миграционный скрипт или `docker-compose.yml`.
- Таблица содержит не все обязательные поля.

### «Незачёт»

Ставится в крайнем случае, если вы присылаете пустое или недоработанное задание во второй раз после отправки работы на доработку.
